# PixelGnome v0.28.0 — Release Notes

**Date:** 2026-06-20
**Type:** Stable — PDF polish + a transparency bug fix (Tier D).
**Against:** v0.27.0

## Headline

A small polish round on the PDF pipelines — finer JPEG control in PDF → Images — plus a transparency bug (black backgrounds when converting transparent images to JPEG) found and fixed during a testing pass.

## Added

- **JPEG quality slider in PDF → Images (D1).** Choosing JPEG output now reveals a quality slider (10–100); it was previously fixed at 85. PNG output stays lossless and unaffected, so the slider only appears for JPEG. The render cache folds quality into its key for JPEG only, so moving the slider re-renders while PNG renders reuse the cache.

## Fixed

- **Transparent → JPEG no longer produces a black background.** The image worker drew onto a transparent canvas and encoded without a backdrop; encoding to JPEG (no alpha channel) filled the transparent areas with **black**. It now composites onto **white** first when the target format is JPEG, matching every other image tool. Alpha-capable outputs (PNG/WebP/AVIF) keep their transparency. This was the root cause of black backgrounds in **Images → PDF** as well (the PDF embeds the converted image; the PDF engine itself handles alpha correctly).
- **`[hidden]` safety rule.** Several components set a `display:` value on their base class, which silently overrode the UA `[hidden]` rule and left attribute-hidden rows visible. Added a global `[hidden] { display: none !important }` — fixes the To-Images quality slider appearing under PNG and the split "custom ranges" row.

## Testing notes

- An automated MuPDF engine regression harness (run in Node) was used to verify the engine: optimize/extract/split/rotate/merge, `imagesToPdf` (real transparent PNG → white via soft mask), and `pdfToImages` (JPEG quality changes output size; PNG ignores it; DPI scales). 17/17 checks pass. The harness is kept outside the repo (in the private backup bundle).
- The canvas-based fixes (`process-worker.js` white-flatten, slider visibility) are browser behaviors confirmed by manual click-test; the engine half of the chain is covered by the harness.
