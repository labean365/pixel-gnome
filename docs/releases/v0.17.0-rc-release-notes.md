# PixelDrop v0.17.0-rc — UX Polish, Multi-Select & Drag-to-Reorder

> **Release candidate.** Feedback-gated before promoting to v0.17.0 stable. Ships the Phase 3 scope from [`docs/audits/2026-04/04-update-plan.md`](../audits/2026-04/04-update-plan.md).

Three sub-phases land together:

- **3a — UX polish**: 10 audit-surfaced gaps closed.
- **3b — Multi-select + bulk actions**: Shift/Cmd/Ctrl-click, bulk toolbar, rotate/flip/delete/download/ZIP on selection.
- **3c — Drag-to-reorder**: HTML5 DnD with drop indicator, plus keyboard `Alt+↑`/`Alt+↓` for a11y parity.

One Phase 3 item — **Bulk apply preset/format to selection** — is deliberately deferred per the plan's "allowed to slip" clause. See [Deferred](#deferred) below.

---

## Highlights

### 🧹 Polish pass (3a)

| Area | Before | After |
|---|---|---|
| Long ops (HEIC / animated GIF / ZIP build) | Silent spinner dot | Determinate progress bar per card / global |
| Drop-zone rejection | Silent ignore | Red-border + shake + descriptive toast (~1.2s) |
| Reset Settings | Blocking `confirm()` — one misclick nukes sizing | Toast with Undo action |
| History drawer | Auto-expands on every entry | Auto-expands once per session (`sessionStorage` sentinel) |
| `localStorage` unavailable | Settings silently don't persist | One boot-time toast |
| APNG / animated WebP | Come in as static, no warning | Magic-byte detection + "animation will be lost" warning |
| Eyedropper canvas | Default options | `{ willReadFrequently: true }` — Safari perf win |
| Help → Pro Tips | 14 bullets (unreadable) | 6 focused bullets; rest moved to tooltips |
| Download All partial failure | Per-file error toasts | "Saved N / M, Errored K" summary toast |
| Preview thumbnails after edit | Always show original | Show processed output when edits exist |

### ☑️ Multi-select + bulk actions (3b)

- **Selection model**: separate `Set<string>` of ids in `main.js` — survives `reprocessAll`, doesn't pollute `BatchItem`, trivial to serialize for future features.
- **Click semantics** (Finder / Explorer convention):
  - Plain click → untouched (still opens editor, downloads, etc.).
  - `Shift`-click → replace with range from the last anchor.
  - `Cmd` / `Ctrl`-click → toggle a single card.
  - **Anchor preservation** across Shift extensions so you can keep extending a range from the original anchor.
- **Visual state**: `.preview-card.selected` with accent border, accent-light tint, 1px accent shadow. `aria-selected` mirrored.
- **Bulk toolbar** (appears when selection ≥ 1): Rotate CCW / Rotate CW / Flip H / Flip V · Download / ZIP · Delete (danger) · Deselect. `aria-live` count span for screen readers.
- **Shared plumbing**: `reprocessAll`, `handleExportAll`, and `handleExportZip` all accept an optional `idsFilter: Set<string>` — one code path for global and selection-scoped runs.
- **Keyboard**: `Delete` / `Backspace` prefers bulk-delete when a selection exists, falls back to focused-card removal otherwise.

### 🔀 Drag-to-reorder + keyboard parity (3c)

- **Drag handle + full-card drag** on every preview card. Delegated handlers on the list root so newly-added cards participate automatically.
- **Drop indicator**: midpoint-split on the target card's bounding rect decides insert-before vs insert-after. 3px accent line painted via `::before` / `::after` pseudo-elements — no layout jitter hovering between slots.
- **State preservation**: `imageQueue` Map is rebuilt in new order (Map preserves insertion order); card DOM nodes are moved manually rather than re-rendering, so ongoing processing bars, blob URLs, edit toolbar wiring, and the `selected` class all survive the reorder.
- **Keyboard reorder (a11y parity)**: cards are `tabindex="0"` with a `:focus-visible` accent ring. `Alt+ArrowUp` / `Alt+ArrowDown` on a focused card calls `handleMoveCard(id, direction)`. Edge hits announce "Already at top/bottom" rather than silently no-oping. After each move, a screen-reader announcement reports "Moved to position N of M".
- **Explicit non-changes in v1**: Reorder is display-only. Filenames are NOT renumbered; ZIP iteration order follows the new display order, but the `{preset}` / `{name}` / `{width}` / `{height}` filename tokens are position-independent, so they're unaffected. An `{index}` / `{order}` token is a tracked stretch goal.

## Deferred

### Bulk apply preset/format to selection

The only Phase 3 item intentionally left out of this RC. It needs a `settingsOverride` field on `BatchItem`, per-item overrides in the worker payload, `processImage` pipeline changes, `reprocessAll` override handling, filename-token resolution for `{preset}`, and a preset-picker UI in the bulk toolbar — meaningful architectural work that's not worth blocking the rest of the polish on.

The existing "change global settings → Download All" flow covers the common case. This ships in the v0.18 cycle.

---

## Known limitations (acceptable for v1)

- **Drag**: no auto-scroll near viewport edges — large queues require manual scroll mid-drag. Drop on the list background (not on a card) is a no-op; drop-at-end works by dropping on the bottom half of the last card.
- **macOS `Ctrl`-click**: also fires the native `contextmenu` event. The selection toggle still runs correctly; the menu flashes briefly. Mac users typically use `Cmd`-click anyway.
- **Keyboard-range-select** (`Shift+Space`) not yet wired — Select All / Deselect All / Delete Selected buttons cover the bulk keyboard path in the meantime.
