v0.24.0-rc — PDF toolkit (compress, organize, merge, convert)

Major feature release candidate. Adds a complete client-side PDF
toolkit alongside the image tools; nothing is uploaded. A lazily-loaded
MuPDF (WebAssembly) engine runs in a Web Worker; the whole feature is
excluded from the portable single-file build.

Added
- Compress/Optimize: structural optimization (recompress images, strip
  metadata, subset fonts, garbage-collect) preserving selectable text
  and vectors. Presets + Advanced controls, multi-page preview,
  before/after size readout.
- Organize: extract / remove / split pages from a thumbnail grid; split
  by every-page or custom ranges (e.g. 1-3, 5, 8-10) into a ZIP.
- Merge: combine multiple PDFs with a reorderable list; multi-PDF drop
  opens Merge preloaded.
- Images -> PDF: combine processed images into one PDF (one page per
  image) from the export bar.
- PDF -> images: rasterize pages to PNG/JPEG at Screen/Standard/Print
  DPI; download a ZIP or send pages into the editor queue.
- Italian translations for all PDF strings; content-free, consent-gated
  analytics (pdf_optimized / pdf_organized / pdf_merged / pdf_rasterized).

Engineering
- New src/modules/pdf/ boundary: pdf-engine.js adapter (sole MuPDF
  importer) behind pdf-worker.js, driven by pdf-ui.js.
- check-pdf-build.mjs build-contract test in verify/pre-push/CI: asserts
  the multi-file build emits worker + separate mupdf chunk + wasm and the
  single-file build excludes them. NOTICE credits Artifex/MuPDF (AGPL).

Fixed
- Merge tab label showed the raw i18n key (pdf.mode.merge); Merge and
  To-Images labels now present in EN + IT.

Verified: npm run verify green (eslint 0 errors, prettier clean,
build:all, check:pdf on dist + dist-single); live-tested all five
operations on pixelgnome.com.
