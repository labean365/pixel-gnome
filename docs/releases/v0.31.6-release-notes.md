# PixelGnome v0.31.6 — Release Notes

**Date:** 2026-10-17
**Type:** Patch — bug fix (LAB-519). Output unchanged; performance/responsiveness only.
**Against:** v0.31.5

## Fixed

### Image worker never loaded in production

`src/modules/batch-manager.js` created the image worker like this:

```js
const workerUrl = new URL('./process-worker.js', import.meta.url);
...
worker = new Worker(workerUrl, { type: 'module' });
```

Vite only bundles a worker when `new URL(...)` is written inline inside `new Worker(...)`. The hoisted form is treated as a plain asset, so `process-worker.js` was copied verbatim into `dist/assets/process-worker-*.js` with its relative imports intact. In the browser those imports (`/assets/shared/dimensions.js`, `/assets/smart-compress.js`) 404'd, the worker's `onerror` fired, and every raster image was processed on the main thread instead. Users saw correct results, but large batches blocked the UI. Likely broken since the shared helpers were split out (before v0.23.0).

Now: `worker = new Worker(new URL('./process-worker.js', import.meta.url), { type: 'module' });` — the same pattern the PDF worker already used. The `data:`/`blob:`/`file:` guard for single-file builds still runs first.

Also: a new `workerFailed` flag stops `initWorker()` from re-spawning a broken worker on every batch (previously `onerror` reset `worker` to `null`, so each new batch tried again).

## Testing

- `npm run verify` green (lint 0 errors, format, build:all, check:pdf, check:pdf-engine).
- `dist/assets/process-worker-*.js` is now a bundled, minified chunk with no `import` statements (was raw source with two relative imports).
- Playwright, 2 large JPEGs (4000×3000, 3000×2000) + a PNG, live v0.31.5 vs this build via `vite preview`:

| Browser | v0.31.5 (live) | v0.31.6 |
|---|---|---|
| Chromium | 404 `shared/dimensions.js`, "Worker error, falling back to main thread" | no 404s, no fallback warning |
| Firefox | "Worker error, falling back to main thread" | no fallback warning |
| WebKit | 404 `smart-compress.js` + `shared/dimensions.js`, fallback warning | no 404s, no fallback warning |

  Output dimensions identical in both builds in all three engines.
