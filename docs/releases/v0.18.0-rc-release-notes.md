# PixelDrop v0.18.0-rc — Presets & Guided Workflow

> **Release candidate.** Feedback-gated before promoting to v0.18.0 stable. Ships the preset-system overhaul, the exact-mode crop preview, and the three-phase guided-workflow redesign specified in [`docs/Preset-System-Spec-2026-06.md`](../Preset-System-Spec-2026-06.md) and [`docs/Guided-Workflow-Spec-2026-06.md`](../Guided-Workflow-Spec-2026-06.md).

## Highlights

This release makes presets *correct* and the app *legible to first-time visitors*, without removing any existing capability.

- **Presets now deliver what their names promise.** Social presets center-crop to the exact labelled size instead of merely fitting inside it.
- **You can see the crop before you export.** Exact-mode presets overlay the keep-region on each thumbnail.
- **The app reads as a 1 → 2 → 3 flow.** Empty-state hero, numbered steps, and a "simple by default" sidebar that folds advanced controls away.

## Presets — library overhaul + fit-vs-crop correctness

- Expanded to **14 built-ins**, grouped via `<optgroup>` into **Web** / **Social** / **Email**, with intent-first names (`Social Square — 1080 × 1080`).
- **Fit-vs-exact fix:** Social presets (Square, Portrait, Story/Reel, Landscape, Open Graph, YouTube, Pinterest, Avatar) use `mode: 'exact'` (center-crop) so the output matches the labelled dimensions. Ceiling presets (Full HD, Large Web, Thumbnail, Email Hero/Retina) stay `fit-within` / `max-long-edge`.
- **Avatar vs Thumbnail** — both 800×800, differentiated by mode (Avatar crops, Thumbnail fits).
- **`neverUpscale` on by default** for all built-ins.
- **Aspect-ratio badges** on exact presets (`1:1`, `9:16`, `1.90:1`, …) via a pure `ratioLabel()` helper.
- **Restore hardening** — an unresolved persisted `presetId` falls back to "Custom" rather than a phantom option.

## Crop preview

- A center-crop overlay (`computeCropKeepRect()` / `updateCropOverlay()` in `preview.js`) draws the keep-region with the trimmed area dimmed on each exact-mode card thumbnail. Pure ratio math that respects the thumbnail's `object-fit: contain` letterboxing; hidden for non-exact modes and when no crop is needed.

## Guided workflow (Phases 1–3)

- **Phase 1** — header tagline; empty-state hero (drop target + privacy line + preset chips) on the formerly-blank canvas, toggled inversely with the preview via `show/hidePreviewArea()`.
- **Phase 2** — numbered sidebar steps (1 Add · 2 Choose a size · 3 Export) with a Step 1 done-check; advanced controls fold into a native `<details>` "Customize" panel that remembers its open state (`pixeldrop-customize-open`) and auto-opens on the Custom preset.
- **Phase 3** — Step 3 export block mirroring Download / ZIP, with a live "N images · ~X MB out" readout (disabled until a result is ready) and a transient "Exported ✓".

## Fixed

- **Toolbar export exported nothing.** `exportBtn` / `exportZipBtn` were wired as `addEventListener('click', handleExportAll)`, so the click `Event` was read as the `idsFilter` argument added in the Phase 3b multi-select work; `Array.from(event)` is `[]`. Wrapped both in arrows. Per-card and bulk-selection exports were unaffected.
- **Empty preview panel could flash on load.** `.preview-area { display: flex }` overrode its `hidden` attribute (no `[hidden]` guard, no global one). Added `.preview-area[hidden] { display: none }`.

## Verification
