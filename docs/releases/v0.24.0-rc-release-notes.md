# PixelGnome v0.24.0-rc — Release Notes

**Date:** 2026-06-19
**Type:** Release candidate — major feature (PDF toolkit)
**Against:** v0.23.0-rc
**Deploy:** Automatic on push to `main` (GitHub Actions → `npm ci` → `npm run build` → publish `dist/`)

## Headline

PixelGnome gains a complete, **client-side PDF toolkit** — compress, organize, merge, and convert PDFs entirely in the browser. Nothing is uploaded, the same privacy promise as the image tools. A multi-MB MuPDF (WebAssembly) engine loads lazily on first PDF use and runs in a dedicated Web Worker off the main thread.

## What's new

**Compress / Optimize.** Drop a PDF to shrink it via true structural optimization — recompress embedded raster images, strip metadata, subset fonts, garbage-collect — while **preserving the selectable text layer and vector content** (it is never rasterized/flattened). Presets (Email / Web / Max), an Advanced panel (quality slider + per-step toggles), a multi-page preview, and an honest before/after size readout (including a clear "already optimized — no reduction" state).

**Organize.** From a page-thumbnail selection grid: **extract** selected pages into a new PDF, **remove** selected pages (keep the rest), or **split** into multiple files — every page individually, or custom ranges like `1-3, 5, 8-10` — delivered as a ZIP.

**Merge.** Combine multiple PDFs into one with a reorderable file list (move up/down, remove per row). Dropping several PDFs at once opens the Merge view with them preloaded.

**Images → PDF.** Combine your processed images into a single PDF (one image per page, sized to each image) directly from the export bar, alongside Download / ZIP.

**PDF → images.** Rasterize every page to PNG or JPEG at a chosen resolution — Screen (96), Standard (150), or Print (300 DPI) — and either download a ZIP or send the pages straight into the editor queue for further resizing/converting. This closes the round-trip between the PDF and image pipelines.

**Localization & analytics.** All PDF strings are translated to Italian. New analytics events (`pdf_optimized`, `pdf_organized`, `pdf_merged`, `pdf_rasterized`) are consent-gated and content-free — they carry only coarse, non-identifying values (bucketed reductions/counts, chosen format/DPI), never filenames or document contents.

## Engineering / hardening

- New `src/modules/pdf/` boundary: a thin `pdf-engine.js` adapter (the only module that imports MuPDF) behind `pdf-worker.js`, driven by `pdf-ui.js`. Swapping the backend means rewriting one file.
- `scripts/check-pdf-build.mjs` build-contract test (wired into `npm run verify`, the pre-push hook, and CI) asserts the multi-file build emits the worker + a separate MuPDF code-split chunk + the wasm, and that the single-file build excludes all of it — guarding the two outage classes hit during development (an undetected worker chunk; top-level await in the worker entry graph hanging a module worker).
- `NOTICE` credits Artifex/MuPDF (AGPL); README documents the runtime dependency and the new features.

## Fixes

- The PDF **Merge** tab label was rendering the raw i18n key (`pdf.mode.merge`) because the string was never added; the Merge and To-Images tab labels are now present in English and Italian.

## Scope / non-goals

- **The image workflow is unchanged** — presets, resize modes, convert & compress, and the export path are untouched (the export bar simply gains a "PDF" button).
- **The single-file build excludes PDF** by design (the engine wasm can't be inlined into one portable HTML file).
- **Italian remains a draft** pending native review.
- Possible follow-ups (not in this release): true DPI downsampling in compress, per-file page selection in merge, page-range selection in To-Images.

## Verification

- `npm run verify` → green: `eslint .` 0 errors (pre-existing warnings only), Prettier clean, `build:all` succeeds, `check:pdf` passes on both `dist` and `dist-single`.
- Production build emits `pdf-worker`, a separate `mupdf-*` chunk, and `mupdf-wasm-*.wasm`; the single-file build emits no `.wasm`.
- Live-tested on pixelgnome.com across all five operations.
