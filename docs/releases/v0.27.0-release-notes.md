# PixelGnome v0.27.0 — Release Notes

**Date:** 2026-06-20
**Type:** Stable — feature (Tier C, C4 mixed-selection export). Completes the Tier C unified file-utility arc.
**Against:** v0.26.0

## Headline

The multi-select workspace now spans **both images and PDFs**, and the bulk actions understand mixed selections. Drop anything, select across types, and export them together — Download, Combine to PDF, or ZIP.

## Added

- **PDF cards are selectable.** The per-card select toggle, Select all / Deselect all, plain click, Shift-range, and Cmd/Ctrl-click, plus the bulk toolbar, now include PDF cards alongside images. The count label reads naturally for mixed sets (e.g. "3 images, 1 PDF").
- **Selection-aware export actions** in the bulk toolbar:
  - **Download** — each selected file in place (images as their processed output, PDFs as-is).
  - **Combine to PDF** — append-merge the whole selection into one PDF in list (DOM) order: images become pages, selected PDFs' pages are inserted in place. Shown only where the PDF feature is available (excluded from the single-file build).
  - **ZIP** — everything together in a single archive (images + PDFs).
- **Mixed delete** removes images (with the usual Undo) and PDFs in one action.

## Changed

- Rotate / flip bulk buttons disable automatically when the selection contains a PDF (they apply to images only); delete and the export actions stay available.
- All-image selections are unchanged — same code paths and behavior as before C4.

## Engineering

- New `combineMixedToPdf(entries)` and `mergePdfBlobs(blobs)` in `pdf-ui.js`, reusing the existing MuPDF worker `pdf-merge` op and `imagesToPdfBlob`; adjacent image runs collapse into one `imagesToPdfBlob` call, PDFs pass through, then all are merged in order.
- `exportAsZip` gained an optional `extraFiles` param so PDFs ride the single ZIP path; existing callers unchanged.
- Selection model generalized to both queues in DOM order (`cardsInDomOrder` / `selectedInDomOrder` / `selectionCounts`).
- Content-free analytics reuse the existing `export` and `pdf_merged` events.
- **Footer version is now injected from `package.json` at build time** via a small Vite plugin (`scripts/vite-inject-version.js`), replacing the hand-edited footer string that had silently drifted (it showed v0.24.0 through the v0.25.0 and v0.26.0 releases). It can no longer go stale.

## Verification

- EN/IT locale parity confirmed for all new `bulk.*` keys; all referenced i18n keys resolve.
- Production build emits the Combine button and the injected footer version.
