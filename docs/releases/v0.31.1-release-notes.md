# PixelGnome v0.31.1 — Release Notes

**Date:** 2026-10-07
**Type:** Patch — bug fixes + one small UX refinement, from the Linear backlog.
**Against:** v0.31.0

## Headline

Real-world SVGs now rasterize at the correct size, numbers follow Italian conventions, and the convert-only panel hides controls that don't apply.

## Fixed

### LAB-173 — SVG sizing

Tested 17 SVG fixtures × 3 output settings (PNG original size, JPEG fit 800, WebP exact 500×500) through `processImage` in Chromium. Basic SVGs, viewBox-only, missing `xmlns`, `currentColor`, XML declaration/DOCTYPE and single-quoted attributes were already fine; sanitization held (script/onload stripped, nothing executed). Four sizing bugs were found and fixed:

| Input | Before | After |
|---|---|---|
| `width="210mm" height="297mm"` (Inkscape A4) | 210 × 297 | 794 × 1123 |
| `width="2in" height="1in"` | **2 × 1** | 192 × 96 |
| `width="100%" height="100%" viewBox="0 0 640 320"` | 100 × 100 | 640 × 320 |
| `viewBox="-10 -10 300 100"` or `"0,0,300,100"` | 1024 × 1024 (distorted) | 300 × 100 |
| `width="600" viewBox="0 0 300 100"` (no height) | 600 × 100 (distorted) | 600 × 200 |

Implementation (`src/modules/image-processor.js`):

- `parseSvgDimensions` now reads only the root `<svg>` tag; `svgLengthToPx` converts CSS absolute units (px, pt, pc, in, cm, mm, Q; em/ex at a 16px root), returns 0 for `%`/`auto`.
- viewBox is split on commas and/or whitespace and accepts a negative origin; a missing width or height is derived from its aspect ratio.
- New `setSvgRootSize` pins the root's width/height to the computed px before rasterizing, so the browser's intrinsic size matches `_svgWidth/_svgHeight` everywhere (also guards against engines that refuse to draw size-less SVGs).
- Thumbnails, the editor source and export all go through `rasterizeSvg`, so they share the fix.

### LAB-25 — Italian decimals

New `formatNumber(value, decimals)` in `i18n.js` (cached `Intl.NumberFormat`, grouping off). Used by both `formatBytes` helpers (preview + PDF UI) and the decimal ratio labels (preview, presets, crop modal). Italian shows "1,84 MB" / "0,71:1"; English output is unchanged. Cards already on screen keep their format on a mid-session language switch (existing LAB-28 limitation).

### Savings row

`outputSize === originalSize` no longer renders "Larger +0 B (+0%)"; the row is hidden.

## Changed

### LAB-34 — convert-only panel

A new `convertOnly` flag in `settings.js` is set when the Original size preset or the Convert recipe is applied (and on load when the saved preset is `original`), and cleared by any other preset/recipe. While it's set and mode is `original`, `#resizeModeGroup` and the now-empty `#sizeModeCol` are hidden; a CSS rule lifts the Processing column into row 1 of the wide layout. Choosing "Keep original size" by hand leaves the radios visible so the user can switch back.

## Not in this release (follow-ups noted on LAB-173)

- Small vector icons (e.g. 24 × 24) still export at their intrinsic size because "Never upscale" applies; SVGs could reasonably be exempt.
- SVG cards show "Larger +7000%" because a raster is always bigger than vector markup — the comparison is not meaningful for SVG input.
- Only tested in Chromium; Firefox/Safari spot-check recommended.
