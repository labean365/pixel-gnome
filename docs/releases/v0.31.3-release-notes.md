# PixelGnome v0.31.3 — Release Notes

**Date:** 2026-10-08
**Type:** Patch — PDF bug fix, dependency update, one UI refinement.
**Against:** v0.31.2

## Headline

Testing the pending Dependabot bump to MuPDF 1.28.1 found that merging it as-is would have broken every PDF save — and turned up a live Split bug in the current engine. Both are fixed, MuPDF and JSZip are updated, and a new engine test now runs in `verify` so this can't slip through again.

## Fixed

### Split produced an empty first file (live since Split shipped)

`PDFDocument.saveToBuffer().asUint8Array()` returns a **view into MuPDF's WebAssembly heap**, not a copy. `split()` saved every part first and the worker copied them afterwards; saving a later part could grow the heap, which detaches earlier views — so they read as **0 bytes**. Reproduced in Chromium on MuPDF 1.27.0 with a 4-page photo PDF: parts were `[0, 8518672]` bytes; now `[2716652, 8518672]`.

Fix: new `saveToBytes(doc, opts)` helper copies the bytes immediately (`.slice()`) and frees the native buffer. All five engine save sites use it.

### MuPDF 1.28 rejects `deflate=yes`

MuPDF 1.28 dropped the `deflate` alias; saving with it throws `Unused pdf arguments found`. Merging the Dependabot PR unchanged would have broken Compress, Split, Extract, Remove, Rotate, Combine-to-PDF and images→PDF. The engine now uses the canonical `compress=yes` (supported in 1.27 too).

## Changed

- **MuPDF 1.27.0 → 1.28.1**, **JSZip 3.10.1 → 3.10.2.** These supersede Dependabot's PRs, which should auto-close once `main` has the newer versions.
- **LAB-481 — SVG size row.** SVG cards show a neutral grey **Rasterized · SVG → PNG/JPG/WebP** row with a tooltip ("SVGs are vector files, so the image version is naturally larger") instead of an amber **Larger +N%**. New i18n keys `card.rasterized`, `card.rasterizedTip` (EN + IT draft).

## Added

- `scripts/check-pdf-engine.mjs` / `npm run check:pdf-engine`, appended to `npm run verify`. Builds four noisy 1600×1100 JPEG pages into a PDF in memory (enough to force heap growth), then asserts getInfo, optimize, extractPages, rotatePages, split (every part non-empty with the right page count), merge and pdfToImages. Confirmed it fails on the old engine with either MuPDF version. ~6 s.

## Testing

- Node engine harness on 3 generated PDFs (12-page text, 4-page photos, 3-page landscape mixed): every operation's results identical between MuPDF 1.27.0 and 1.28.1 (with the fix).
- Browser, via the real `pdf-worker.js` in Chromium on 1.28.1: info / optimize / extract / rotate / split / merge / rasterize / preview all succeed for all three files.
- SVG cards checked in EN and IT; JPG cards unchanged (Saved / Larger).

## Not changed

- Dependabot's other two PRs (dev-dependency group: eslint/prettier/vite/globals; `actions/setup-node` 6 → 7) are left for a separate pass — the second edits a workflow file, which may re-trigger GitHub's deploy-approval prompt.
- CI (`pixel-gnome-build.yaml`) still runs only the build + build-contract check; adding the engine test there is a possible follow-up.
