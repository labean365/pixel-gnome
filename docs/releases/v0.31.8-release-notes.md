# PixelGnome v0.31.8 — Release Notes

**Date:** 2026-10-17
**Type:** Patch — behavior change for SVG input only (LAB-480).
**Against:** v0.31.7

## Changed — SVGs may scale up

Before: a 24×24 SVG exported with "Fit within 800" came out at 24×24, because the fit modes never enlarge and "Never upscale" treated the SVG's intrinsic size as its original. That rule protects raster images from going soft, but a vector loses nothing when enlarged.

Now:

- `calculateDimensions(src, settings, { isVector })` in `shared/dimensions.js`: with `isVector`, `fit-within` and `max-long-edge` scale up to the target, and `exact` ignores `neverUpscale`. `original` is unchanged. Raster callers (main thread and worker) pass nothing and behave as before.
- `image-processor.js` SVG path: target computed first; when it's larger than the (edited) intrinsic size, `rasterizeSvg(file, undefined, scale)` re-renders the SVG with its root pinned to `scale ×` the intrinsic px, so the canvas draws a sharp, full-resolution raster instead of stretching a small one. Crop edits are fractional (`edits.crop.{x,y,w,h}`), so they apply to the larger render unchanged. `_svgWidth/_svgHeight` still report the intrinsic size (card "original" label unaffected).
- Edge-case guards (raster too): fit-within with neither width nor height, and max-long-edge with no edge, now return the source size instead of NaN.

## Testing

- `npm run verify` green.
- `calculateDimensions` table test, 12 cases: SVG upscales in fit / long-edge / exact; raster 24px stays 24px in all modes; SVG and raster downscales identical to before; `original` unchanged.
- Browser (Chromium, Firefox, WebKit) via `processImage` on a 24×24 circle icon: Fit 800 → 800×800; Exact 1080×1350 (Never upscale on) → 1080×1350; Fit 800 + crop left half → 400×800; Original → 24×24. Edge sharpness check: 1–2 anti-aliased pixels at the circle edge on the middle row (a stretched 24px raster would be a ~33px blur).
