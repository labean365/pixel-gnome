# PixelGnome v0.29.0 — Release Notes

**Date:** 2026-06-22
**Type:** Minor — two Tier D PDF features.
**Against:** v0.28.1

## Headline

Page-range export in **To Images** (render just the pages you select) and **batch optimize** for PDFs (compress several at once from the workspace). Both lean on the unified workspace + drill-in grid that Tier C built, rather than adding new standalone surfaces.

## Added

### D2 — page-range in To Images

- The drill-in editor's page grid now feeds the rasterizer. The To Images panel gets an **All pages / Selected (N)** toggle; "Selected" renders only the pages currently selected in the grid.
- Output filenames keep the **original page numbers** (e.g. `doc-p03.png`), so a subset is still labelled correctly.
- "Selected" is disabled until you select pages; clearing the selection auto-reverts to All. The render cache and progress count are scoped to the chosen pages.
- Engine: `pdfToImages` gained an optional `pages` array (0-based indices, in order; out-of-range dropped; omitted ⇒ all). Backward compatible.

### D6 — batch optimize selected PDFs

- With 2+ cards present, selecting one or more PDFs reveals **Optimize PDFs** in the bulk toolbar (only shown when the selection contains a PDF, and only when the PDF feature is compiled in).
- Each selected PDF is optimized **in place**, sequentially, with a per-file progress toast, using the engine's default structural-optimize settings (same as the in-modal Compress default preset: recompress images, strip metadata, subset fonts, garbage-collect — text/vectors preserved).
- Cards update to their smaller file and refreshed page meta. A PDF that can't be beaten is left as-is (the engine returns the original bytes when it can't shrink it). A summary toast reports how many shrank and the total % saved.
- New headless helper `optimizePdfBlob(blob, options)` in `pdf-ui.js` drives the existing `pdf-optimize` worker op; no new engine primitive.

## New i18n keys (EN + IT)

- `pdf.img2.pages`, `pdf.img2.scopeAll`, `pdf.img2.scopeSelected` ({count}).
- `bulk.optimize`, `bulk.optimizeTip`, `bulk.optimizeAria`, `bulk.optimizingN` ({done}/{total}), `bulk.optimizeStart` ({count}), `bulk.optimizeDone` ({count}/{pct}), `bulk.optimizeFailed`.

## Deferred

- **D3 (per-file page selection in Merge)** was specced against the in-modal Merge tab that Tier C removed (merging is now the workspace "Combine to PDF" action). Swapped out for D6 this release; D3 can return later as its own scoped item if demand appears.
- Remaining Tier D: D4 true DPI downsampling (heavy — no direct pixmap resample in MuPDF). Tier E (i18n/SEO; Italian native review still gates dropping "draft") and Tier F (infra) unchanged.

## Build-detection safety

No worker/bundling-sensitive code changed — the `pdf-rasterize` and `pdf-optimize` ops already existed; D2 only adds an option field and D6 reuses the optimize op. Build contract (pdf-worker + mupdf chunk + wasm in `dist`; none in `dist-single`) is unaffected.

## Testing notes

- Full `npm run verify` (lint / format:check / build:all / check:pdf) green in a faithful Linux build (`npm ci`). eslint: 0 errors.
- Engine harness extended with a `pdfToImages` subset check (renders only requested indices, in order) and re-run.
- Manual live checks: select a few pages in the grid → To Images → Selected (N) → ZIP has only those pages with correct numbers; select 2+ PDFs → Optimize PDFs → cards shrink, summary toast shows savings.
