# PixelGnome v0.28.1 — Release Notes

**Date:** 2026-06-22
**Type:** Patch — PDF robustness + privacy copy (hardening). No new features.
**Against:** v0.28.0

## Headline

A small hardening round surfaced by a pre-feature health check: three sturdier failure modes in the PDF path, plus privacy wording that now reflects PDFs being first-class (not just images).

## Added

- **PDF worker watchdog (`pdf-ui.js`).** `call()` now arms a 60s no-response timer per request that is **re-armed on every progress tick**, so long multi-page renders/optimizes that keep streaming progress are never killed, while a worker that fails to instantiate or wedges mid-op rejects with a clear message and tears the worker down (the next call re-creates a fresh one). Previously a worker that never started could leave the modal spinning forever.
- **`%PDF-` signature check on intake (`main.js`).** `handleNewFiles` now sniffs the first 5 bytes (`looksLikePdf`) before committing a PDF card, so an extension-spoofed or corrupt-header `.pdf` is rejected up front with a toast instead of becoming a placeholder card that only fails when clicked.
- **Zero-page PDF empty state (`pdf-ui.js`).** `openPdfModal` detects `pageCount === 0` and shows "This PDF has no pages." instead of building a blank editor grid.

## Changed

- **Privacy copy covers PDFs (EN + IT).** The privacy panel ("Local processing", "No uploads, no storage", "Analytics", "Use at your own risk"), the cookie-consent banner, and the analytics description previously said only "images"; they now say your images **and PDFs** are processed locally and never uploaded. (G1 from the roadmap.)

## New i18n keys (EN + IT)

- `pdf.errorTimeout`, `pdf.errorNotPdf` ({name}), `pdf.errorEmpty`.

## Not touched

- The in-app changelog modal (`changelog-modal.js`) is a curated highlights list last updated at v0.24.0; consistent with the C/D releases, this patch doesn't add an entry there.
- IT strings remain in the existing **draft** state (native-speaker review is the separate E1 gate).

## Testing notes

- Full `npm run verify` (lint / format:check / build:all / check:pdf) green in a faithful Linux build (`npm ci` in a throwaway copy). eslint: 0 errors. Build contract holds on `dist` (pdf-worker + mupdf chunk + wasm) and `dist-single` (no wasm).
- The MuPDF **engine** code is unchanged in this release, so the engine regression harness (17/17 at v0.28.0) still applies; the changes here are UI/intake/copy.
- Manual live checks to run post-deploy: drop a non-PDF renamed to `.pdf` (expect rejection toast); confirm the privacy panel + consent banner mention PDFs.
